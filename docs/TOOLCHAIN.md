# Canonical toolchain

`config/toolchain.json` is the human-readable manifest. `scripts/toolchain/verify.mjs` checks every
enforcing declaration, the npm lock root, exact direct dependency specifiers, `.npmrc`, the absence
of a competing pnpm lock, and the running Node/npm versions.

| Tool                     | Exact version     |
| ------------------------ | ----------------- |
| Node.js                  | 22.22.2           |
| npm                      | 11.4.2            |
| Python                   | 3.13.13           |
| uv                       | 0.7.22            |
| Neo4j Community local/CI | 5.26.28-community |
| Neo4j Python driver      | 5.28.2            |
| TypeScript               | 5.8.3             |
| Vite                     | 7.3.6             |
| Wrangler                 | 4.126.0           |
| k6 workflow image        | 1.0.0             |

Vite 7.3.6 is an intentional security reconciliation of the earlier proposed 7.0.4 pin. Direct
JavaScript and Python dependencies remain exact. Automation uses `npm ci` and `uv sync --locked`;
lockfiles are generated by package managers, never hand-edited. npm install-script approval is
pinned to the exact esbuild, workerd, and optional fsevents versions present in the lock, so CI does
not make an interactive supply-chain decision. Weekly grouped Dependabot PRs cover frontend
production/development, Python, Actions, and Docker images.

Local verification:

```bash
npm ci
npm run toolchain:check
npm run check
cd services/alchemy-api
uv sync --locked --all-groups
uv run alchemy check
```

Docker uses the exact Python tag rather than a digest because the repository does not yet have an
automated multi-architecture digest refresh and provenance workflow. Dependabot supplies reviewed
base-image updates.

The four language/runtime entries are the exact versions provided by the configured Codex Cloud
universal environment when its package selectors use Node `22` and Python `3.13`. Development does
not replace them during setup. GitHub Actions and the Render container declare the same versions;
Cloudflare reads exact Node from the root version files and must use exact npm during the release
activation. Local tooling, lockfiles, and API metadata follow the same contract. If the managed Cloud
image advances a patch, update the repository and production declarations together through a
reviewed pull request instead of installing a second hidden runtime inside Cloud.
