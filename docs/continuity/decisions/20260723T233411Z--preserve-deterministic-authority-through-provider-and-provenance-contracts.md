# Decision: Preserve deterministic authority through provider and provenance contracts

- Status: accepted
- Date (UTC): 2026-07-23
- Scope: Astrology data architecture and product truthfulness

## Context

The alpha needs realistic UI data before verified calendrical, organ-clock, relationship, or personal
engines exist. The product principles prohibit fabricated traditional calculations and require global,
personal, and synthesized signals to remain distinguishable.

## Constraints and requirements

- Deterministic engines and curated sources must remain authoritative for computed facts.
- Missing information must be labeled rather than inferred.
- Demo data must not be presented as the actual temporal configuration.
- Domain data and calculation boundaries must remain independent from Vue presentation.

## Options considered

1. **Embed fixtures or interpretation directly in Vue components** — rejected because it couples data
   truth to presentation and scatters demo-only conditions.
2. **Implement traditional algorithms from incomplete source material** — rejected because no verified
   calculation source or canonical dataset is present.
3. **Use a stable provider contract with status and provenance** — accepted because it supports a
   polished alpha while preserving a swappable seam for verified engines.

## Decision

All Astrology snapshots pass through `CurrentFlowProvider`. Every display datum carries availability
status and source information, and each snapshot includes provider-level provenance. The alpha binds
the interface to `DemoCurrentFlowProvider`, which explicitly states that no calculation occurred.

## Rationale and supporting evidence

The implemented domain types separate temporal, organ, synthesis, and provenance data. The provider
adapter centralizes fixtures, while the UI renders status supplied by the snapshot. Tests confirm the
demo status and no-calculation note. This matches the documented product and data-integration rules.

## Consequences and tradeoffs

- Verified local or API providers can replace the demo adapter without rewriting presentation.
- The alpha remains evaluable without misrepresenting fixture data.
- Status and provenance add contract and UI complexity.
- No production timing claim is possible until authoritative providers exist.

## Implementation or migration implications

- Future engines implement `CurrentFlowProvider` or adapt their output to it.
- Deterministic facts must not be generated by the synthesis layer.
- Personal context requires a separate contract before synthesis.

## Verification criteria

- Demo snapshots and each temporal/organ item are visibly labeled `demo`.
- Provider tests assert the no-calculation provenance note.
- No calendrical algorithm or unverified lookup table appears in presentation code.
